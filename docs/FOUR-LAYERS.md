# Four layers and an evidence-preserving update loop

Venus stores and organizes knowledge; the configured model/tool runner performs analysis. Once a local job is enabled, the built-in coordinator records request, returned result, actual save, readback and the next saved boundary. It does not require a chat reminder loop. Import/update, model return, file save and full-scope verification are different states.

| Layer | What it keeps | Generic example | Boundary |
|---|---|---|---|
| Vault | Original conversation/document and source identity | Original notes about a test procedure | Logical grouping is not a substitute for the original text. Missing material stays marked. |
| AI knowledge | Facts, experience, conditions and evidenced associations | Which checks distinguished a failed request from an uncertain save | A recorded claim is not automatically a universal fact or the user's confirmed position. |
| AI skills | A complete reusable prompt: task, knowledge, common settings, criteria, inputs, steps, output and negative conditions | Apply the test procedure; or reuse a stable fictional character with one selected style/outfit variant and this request's increment | Legacy method use may be unreviewed. Reference retrieval does not authorize execution or prove proficiency. |
| Concept cloud | Human-readable complete overview and developing understanding | Project goals, reasoning, open questions and conclusions in one layered page | User information, AI inference and confirmed conclusions must remain distinguishable. |

The common navigation is **semantic domain → project → content/subtopic**. One project can be referenced from several domains using the same stable ID; original material is not duplicated. The layers have different responsibilities and share traceable sources, rather than acting as four synonymous tag stores.

## Updating content, configuration and derived organization

1. **Content synchronization:** explicitly authorized source packages and edits update the local library. Deduplication uses current identities/hashes; it does not promise access to an entire account or collect every new chat automatically.
2. **Configuration/templates:** edit and confirm the relevant layer template for future requests. Help is separate. Confirming a template starts no model job and does not silently reanalyze old files.
3. **Derived organization:** use explicit bounded semantic-label maintenance or authorized selected reanalysis. Preserve original returns, source proof and used budgets. Pending, unknown and deferred work remains visible; a changed view is not proof of a newly saved analysis.
4. **Reuse:** call the read-only task-context endpoint with selected IDs, then include its actual bounded response in the AI request. The interface alone does not inject memory into the current chat or enable another platform.

Stable common identity/settings should be kept separately from variant differences and a request's current change. For a synthetic example, select the violet outfit, add a silver clip, retain the shared character definition, and explicitly exclude other outfit variants. Missing settings and conflicting sources must be surfaced rather than invented.

The model still needs valid access, explicit scope and enough source context. Venus does not make arbitrary autonomous edits to its own architecture or guarantee correct automatic organization. Personal data sent to a configured cloud analyzer is subject to that selected analysis request; enabling one connection is not authorization for every platform.
